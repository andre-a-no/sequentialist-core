# sequentialist-core

Общий слой семейства sequentialist (`sequentialist.core`): spec'и,
движок с журналом и контрольными точками, хранилища, аудит, отчёты,
симуляции, replay, доставка, псевдонимы, общий CLI. Версия 0.1.0 выпущена
тегом `v0.1.0` (2026-10-28).

## Семейство

Библиотеки sequentialist — прикладной слой над ядром
[sequential-analysis](https://github.com/andre-a-no/sequential-analysis)
(PyPI `sequential-analysis`, импорт `sequential_analysis`, зависимость
`>=0.4,<0.5`). Каждая библиотека живёт в своём репозитории и ставится
отдельно; общее пространство имён `sequentialist` (PEP 420, без
`__init__.py` на этом уровне).

| Репозиторий | PyPI | Импорт |
|---|---|---|
| sequentialist-core | `sequentialist-core` | `sequentialist.core` — общий слой |
| sequentialist-ab | `sequentialist-ab`, npm `@sequentialist/ab-client` | `sequentialist.ab` |
| sequentialist-quality | `sequentialist-quality` | `sequentialist.quality` |
| sequentialist-monitor | `sequentialist-monitor` | `sequentialist.monitor` |
| sequentialist-markets | `sequentialist-markets` | `sequentialist.markets` |
| sequentialist-clinical | `sequentialist-clinical` | `sequentialist.clinical` |
| — (позже) | `sequentialist-release`, `sequentialist-mlops` | |
| sequentialist-messengers (будет заведён) | `sequentialist-messengers` | `sequentialist.messengers` — слой над core: каналы сообщений людям, ответы привязанных людей |
| sequentialist-visuals (будет заведён) | `sequentialist-visuals` | `sequentialist.visuals` — слой над core: инфографика общего рода (SVG/HTML) |

Пока sequentialist-core нет на PyPI, прикладные пакеты ставят его из git:
по коммиту `27f71847ea39cedf0a8e41a5f05042428a533443` (подкаталог
`packages/core`) или по тегу `v0.1.0` (без подкаталога) — код один и тот
же. Когда core появится на PyPI, перейти на `sequentialist-core>=0.1,<0.2`.

**Слои над core** (решение владельца): универсальное, но не входящее в
core — свой пакет поверх core. sequentialist-messengers: интерфейс канала,
заглушка и реализации мессенджеров; зависимости от SDK мессенджеров под
своими лицензиями остаются в нём (проверять лицензии перед добавлением).
sequentialist-visuals: графики и инфографика общего рода (ряды с
полосами, распределения, автокорреляции, диаграммы рассеяния, границы
последовательных процедур, контрольные карты) — SVG и HTML на стандартной
библиотеке, без JS-библиотек и внешних ресурсов, светлая и тёмная тема,
гарантия у каждого числа. Visuals только рисует: всё, что считается
(автокорреляции, плотности, границы), считает ядро или вызывающий пакет.

## Постоянные правила

- **Статистика — только в ядре.** Ядро (sequential-analysis) отсюда не
  править; чего не хватает — список запросов: что нужно, зачем, какой
  интерфейс.
- **Что попадает в core:** то, что нужно хотя бы половине прикладных
  пакетов (сейчас их 7, порог 4); что уже в core, обратно не выносится.
  Удаление из core — несовместимое изменение API, решает владелец.
- **Совместимость.** Прикладные пакеты закрепляют
  `sequentialist-core>=0.1,<0.2`; в пределах 0.1 API только расширяется.
- **Гарантии.** Каждый вывод называет свою гарантию (`exact`, `asymptotic`,
  `model`, `approximate`, `none`) так, как её объявляет процедура ядра.
  Утверждения честные и сдержанные; ничего не обещать без проверки тестом.
- **Сверка с эталонами.** Каждая процедура и каждый результат сверяются с
  внешней эталонной реализацией или закрытой формулой, где она есть.
- **Python ≥3.8**, обязательных зависимостей, кроме ядра и core, нет.
  Перед пушем: `ruff check .`, `mypy`, тесты, `vermin -t=3.8-`; CI должен
  быть зелёным.
- **Лицензии:** AGPL-3.0-only или коммерческая (COMMERCIAL.md); в каждом
  исходном файле SPDX-заголовок без города.
- **Чужой код принимается только по CLA** (`CLA.md`): без него код
  участника нельзя предлагать по коммерческой лицензии. PR без
  подписанного CLA не сливать. В CLA нет оговорки о подсудности и нет
  города — так решил владелец.
- **Этот файл (`CLAUDE.md`) оставлен по решению владельца.** Правило
  «никаких инструкций для мейнтейнеров в репозитории» — про заметки для
  людей (как выпускать, памятки себе), а не про этот файл.
- **Контакты** в публичных файлах — только email: a.hobukob@gmail.com,
  andrei@hobukob.ru. Никаких телефонов, адрес компании не указывать.
- **Никаких идентификаторов моделей** в коммитах, PR и коде.
- **Персональные данные:** 152-ФЗ и GDPR; движок работает с псевдонимами,
  хэшами и агрегатами.
- PR — только по просьбе владельца; ничего не мержить без его явного
  подтверждения.
- Общение с владельцем — по-русски; код, документация и коммиты —
  по-английски.

## Особенности этого репозитория

- Прототип сервиса мониторинга до перестройки в семейство — коммит
  `94c1b35`; его журнал, контрольные точки и сегменты перешли в
  `sequentialist.core`.
- Ограничения 0.1 (в README): состояние задачи пишется целиком на каждой
  контрольной точке; блокировки — в пределах одного хоста (Postgres —
  позже, в пакете, которому он нужен).
- Публикация на PyPI — `.github/workflows/publish.yml`, Trusted Publishing:
  издатель на PyPI должен совпадать буква в букву: владелец `andre-a-no`,
  репозиторий `sequentialist-core`, workflow `publish.yml`, environment
  `pypi`. Запускается публикацией
  GitHub-релиза или вручную с указанием тега; тег должен быть `v` +
  версия из `version.py`, иначе публикация останавливается.
